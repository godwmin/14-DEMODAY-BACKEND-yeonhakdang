# 주문별 결과 고정 저장

결제사 연동과 독립적으로 동작합니다. 결제 완료는 기존 서버 검증 경로만 결정합니다. 클라이언트의 결과 저장 요청은 주문 상태나 구매 권한을 변경하지 않습니다.

## 저장과 열람

- 주문 생성 후 결제창 준비 전에 `PUT /api/orders/{id}/result-snapshot`으로 구매 당시 입력, 대학·관계 선택, 완성된 결과 모델을 저장합니다.
- 저장 실패 시 프론트는 결제창을 열지 않고, 백엔드 prepare도 저장된 결과가 없는 주문을 거절합니다.
- 스냅샷은 수정할 수 없습니다. 동일 요청의 재전송은 허용하고 다른 내용은 CONTENT_IMMUTABLE로 거절합니다.
- 현재 결과 생성 엔진은 프론트에 있습니다. 저장한 모델은 클라이언트 생성 자료이며 서버에서 사주 계산을 검증한 자료는 아닙니다. 결제 금액·상태·권한은 서버 기록만 사용합니다.
- `POST /api/orders/{id}/saved-results/{kind}/open`은 현재 사용자 소유의 PAID/PARTIALLY_REFUNDED 주문과 ACTIVE 권한을 검사한 뒤 저장된 결과를 반환하고 최초 열람 시각을 기록합니다.
- 저장 결과가 없는 예전 주문은 SAVED_RESULT_MISSING으로 안내합니다. 현재 입력으로 대체 결과를 만들거나 열람했다고 기록하지 않습니다.
- 보관함은 최신 구매를 열고, 구매 내역의 다시 보기 버튼은 해당 과거 주문을 엽니다.

## 부적

구매 당시 4개 디자인(최초 + 다시 뽑기 3회)을 저장합니다. 다시 뽑기는 서버의 현재 variant를 조건으로 증가시키며, 다른 기기에서도 마지막 디자인과 남은 횟수를 복원합니다. 오래된 창의 중복 요청과 3회 초과 요청은 거절합니다.

## 데이터와 배포

V1_2 마이그레이션이 order_result_snapshot 테이블을 생성합니다. 탈퇴하면 개인 입력과 결과 스냅샷을 삭제하고 거래 기록은 기존 정책대로 남깁니다. 환경변수 추가 없음. 백엔드 배포 완료 후 프론트를 배포합니다.

모의 PaymentGateway를 사용한 테스트는 결제 완료 전 열람 차단, 결제 완료 후 다른 세션 복원, 결과 불변성, 소유권·CSRF·환불 차단, 최초 열람 기록, 부적 횟수 제한 및 탈퇴 후 삭제를 검증합니다. 실제 페이앱 결제 성공을 검증한 것은 아닙니다.
