# 계정 간 쌍방 초대

카카오 로그인한 사용자가 공유하기에서 링크를 만들면 서버가 발급한 `?inviteId=<UUID>` 주소를 사용합니다. 받은 사람이 로그인·필수 동의·분석을 완료하면 양쪽 계정의 동기 명단에 서로 등록됩니다. 게스트 분석은 계속 사용할 수 있으며, 로그인 후 쌍방 등록을 완료합니다. 게스트가 생성한 기존 형식 `?invite=` 링크는 받은 사람의 명단에 추가하는 방식으로 계속 동작합니다.

`POST /api/invitations`는 로그인한 사용자의 초대 토큰을 발급합니다. `GET /api/invitations/{token}`은 초대한 사람이 공유한 이름과 분석 입력을 반환합니다. `POST /api/invitations/{token}/accept`는 로그인·동의·분석 완료 상태를 확인해 한 건의 계정 관계를 생성합니다. 본인 링크, 반복 수락, 역방향 수락은 중복 관계를 만들지 않습니다. 두 계정의 잠금 순서를 고정해 동시 수락을 처리합니다.

`GET /api/me/friends`는 현재 계정의 관계와 상대방의 최신 분석 입력으로 명단을 구성합니다. 프론트는 화면 복귀·새로고침·약 15초 간격으로 갱신합니다. 이 명단은 개인 분석 스냅샷에 복제 저장하지 않습니다. 탈퇴 시 해당 초대 토큰과 양방향 관계를 삭제합니다.

V4 마이그레이션과 백엔드 배포가 먼저 필요합니다. 추가 환경변수는 없습니다. 예전에 만든 링크는 초대한 계정을 식별할 수 없어 소급 쌍방 등록하지 않습니다. 배포 후 로그인 상태로 새 링크를 생성해야 합니다.

검증은 서로 다른 계정의 양쪽 명단, 중복·본인·동시 수락, 동의/분석/인증/CSRF 조건, 프로필 수정 반영, 탈퇴 후 제거를 포함합니다. 실계정 확인은 A 로그인·분석·새 링크 공유 → B 링크 열기·로그인·분석 → 양쪽 명단 확인 순서입니다. B가 게스트로 먼저 분석한 뒤 로그인하는 흐름도 확인합니다.
